# Amazon Bedrock

A runner owner can open **Settings → Bedrock**, choose an AWS region and authentication method, and enter the model IDs available to that runner. Bedrock appears as a session source for each harness that has at least one configured model and a credential configuration.

## Credentials and models

- **Bedrock API key** uses an Amazon Bedrock bearer token. Save the token in the key field. The runner stores it in its private credentials file and returns only its last four characters.
- **AWS profile** uses a named profile from the runner service account’s AWS configuration. An IAM access-key profile, assumed role or IAM Identity Center profile can supply the signing credentials. For IAM Identity Center, run `aws sso login --profile YOUR_PROFILE` as the runner account before sending. Renew the login there when it expires. [AWS API keys](https://docs.aws.amazon.com/bedrock/latest/userguide/api-keys.html) · [AWS CLI profiles](https://docs.aws.amazon.com/cli/latest/userguide/cli-configure-files.html)
- **Claude** uses the Bedrock Runtime Invoke API. Enter a foundation model ID, a system inference profile ID such as `global.anthropic.claude-sonnet-4-6`, or an application inference profile ARN. Allow `bedrock:InvokeModel` and `bedrock:InvokeModelWithResponseStream` for the models and profiles you use. Claude Code also uses profile lookup permissions for inference profile metadata. Tether pins Claude Code’s startup and background model defaults to the selected ID. [Claude Code on Bedrock](https://code.claude.com/docs/en/amazon-bedrock)
- **Codex** uses the Bedrock Mantle Responses API. Enter an ID available on that endpoint in the configured region, such as `openai.gpt-oss-120b` or `openai.gpt-5.6-sol` where available. Allow `bedrock-mantle:CreateInference` for the AWS account’s project. [Bedrock Responses API](https://docs.aws.amazon.com/bedrock/latest/userguide/inference-responses-api.html)

The configured entries populate the Model menu for Bedrock sessions. The first entry for a harness is its Bedrock default. A first-party alias lets source switching match an existing model to a Bedrock ID. An unmatched manual switch uses the first Bedrock entry. A switch back uses the destination’s default unless you select a model for the pending switch. Plan fallback requires a matching configured ID or alias when the session has a selected model.

## Cost and spend guard

Tether estimates request cost from reported input, output and cache counts. Its dated US East (N. Virginia) table covers the listed Claude Sonnet 4.6 inference profiles and GPT-OSS models. Enter rates in USD per million tokens to override the table or price another model, region or application inference profile. Session totals show partial coverage when a request lacks usable usage or rates. Claude's terminal inference counts toward the runner’s guard, and the session chip marks terminal coverage as partial. [AWS Bedrock pricing](https://aws.amazon.com/bedrock/pricing/) · [AWS regional price lists](https://docs.aws.amazon.com/awsaccountbilling/latest/aboutv2/using-ppslong.html)

The optional **Daily spend guard** shares one running total across both harnesses on the runner. It stops new inference once the estimate reaches the limit, or when a submitted request leaves unpriceable usage. Requests in progress can finish and can take the total above the threshold. The guard resets at midnight UTC. It covers inference through this Tether runner. Account-wide spend, taxes, discounts and charges outside Tether appear in AWS Billing. [AWS Budgets](https://docs.aws.amazon.com/cost-management/latest/userguide/budgets-managing-costs.html)
