# P1 acceptance: Claude, live

Manual checks for P1: discovery, stored sessions, live driving of Claude Code, sync across devices,
subagents, paging, and errors. Each check gives exact steps and the expected result. "Desktop" means
a browser window at least 1024 px wide. "Phone" means a real phone, or a browser at 375 × 812 with
touch emulation.

Phase acceptance (SPEC §11):
- Start a turn on desktop, close the tab, open the session on the phone mid-turn and watch it stream (E3).
- After the turn, both devices show identical transcripts (E1, E2).
- A session started in a terminal `claude` shows up (B4, B5).

## Setup

Use the isolated dev stack. Never use the production runner (`systemctl --user` unit
`tether-runner`) or `~/.config/tether`.

```sh
mkdir -p ~/.local/share/tether-dev && echo '{"runnerId":"tether-dev","name":"tether-dev"}' > ~/.local/share/tether-dev/runner.json
# a scratch project, so test sessions don't clutter real ones
mkdir -p ~/.local/share/tether-dev/projects/scratch && cd ~/.local/share/tether-dev/projects/scratch \
  && git init -q && printf 'export const add = (a: number, b: number) => a + b;\n' > math.ts \
  && printf '# Scratch\n\nA scratch project for Tether tests.\n' > README.md && git add . && git commit -qm init
# terminal 1: server on :8790
cd server && env -u FOLIATION_ISSUER -u PORT bun src/index.ts
# terminal 2: runner (unset any production TETHER_URL / TETHER_TOKEN your shell carries)
cd runner && env -u TETHER_URL -u TETHER_TOKEN TETHER_DEV=1 TETHER_CONFIG_DIR=~/.local/share/tether-dev bun src/index.ts
# terminal 3: web on :5180
cd web && bunx vite
```

Open http://127.0.0.1:5180. To use a phone, tunnel the port (`ssh -L 5180:127.0.0.1:5180 host`).
Unless a check says otherwise, new sessions use **Haiku** in the scratch folder with **Bypass
permissions**. P1 has no approval prompts, so in the other modes Claude's edits and commands are
declined (section H).

Automated parts:
- `for p in shared server runner web; do (cd $p && bun test && bunx tsc -p .); done`
- `bun scripts/smoke-p1.ts`: scripted browsers driving real Claude through the relay.
- `node scripts/e2e-p1.mjs`: Playwright at desktop and phone size against real Claude. See the header of the file for its environment variables.

### Terms

- **Session row:** a sidebar row. The title is on the first line. The second line shows the
  harness glyph (✻ for Claude Code), the project folder name, how long ago, and a status dot while
  the session runs.
- **Running:** the composer's send button is a **Stop** button, and the row's dot is on.
- **Idle:** the send button is back. Its arrow is disabled while the box is empty.
- **Notice:** a quiet line in the transcript, not a chat bubble. Info is grey, warning amber, error red.

## Deliberately left for later

- **The reset size (review m6).** A `reset` (a rewind, or a store change touching more than 50 messages) carries the newest page capped at 2 MB, as a snapshot does. It isn't smaller.
- **The effort label (review m13).** A stored session whose effort comes from your Claude settings shows that level ("High") rather than "Default", even when it was never picked in Tether.
- **The parsed-file cache (review m5).** At most 4 session files stay parsed in memory. A very long session can still hold tens of MB while it's watched.
- **Workflow agents.** A Workflow run's agents (`subagents/workflows/<run>/agent-*.jsonl`) are listed
  among the session's subagents and open like any subagent, but the Workflow card doesn't link to
  them: their meta files name no tool call, and one card would need a link per agent.
- **Steering subagents.** It goes through the main agent's SendMessage tool, and arrives in P5.
