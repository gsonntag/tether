# P3 acceptance: terminal mode

Manual checks for P3: the Terminal button, Claude's TUI in tmux (handoff both ways), the read-only
transcript, the phone key bar, the composer's messages waiting for Back to Tether, "Needs you" from
the TUI's hooks (Tether doesn't follow the TUI's turns), the stop-and-open prompt with held queued messages, project shells, two devices, reconnects
and runner restarts. Each check gives exact steps and the expected result. "Desktop" means a browser
window at least 1024 px wide. "Phone" means a real phone, or a browser at 375 × 812 with touch
emulation.

Phase acceptance (SPEC §11):
- Open the terminal mid-session (A2).
- Use a Claude-only feature in the TUI, e.g. the `/model` picker (B1, B6).
- Go back to Tether, and the next message continues the same conversation (D1).
- The terminal survives a runner restart (H4).
- Phone and desktop attach together without a garbled layout (G1–G3).
- A project shell running a dev server is still there after the panel closes (I2).

## Setup

An isolated dev stack with its own ports, config and tmux socket, so it runs beside a production
runner and other dev stacks:

```sh
D=~/.local/share/tether-dev-p3
mkdir -p $D/projects/scratch $D/projects/shellproj && echo '{"runnerId":"tether-dev-p3","name":"tether-dev-p3"}' > $D/runner.json
cd $D/projects/scratch && git init -q && echo '# Scratch' > README.md && git add . && git commit -qm init
# Claude asks once whether to trust a new folder: run `claude` there once and pick "Yes, I trust this folder".
# server on :8792
cd server && env -u FOLIATION_ISSUER -u PORT -u TETHER_URL -u TETHER_TOKEN PORT=8792 bun src/index.ts
# runner, with its own tmux socket
cd runner && env -u TETHER_URL -u TETHER_TOKEN TETHER_DEV=1 TETHER_URL=http://localhost:8792 TETHER_TOKEN=dev \
  TETHER_CONFIG_DIR=$D TETHER_TMUX_SOCKET=tether-dev-p3 bun src/index.ts
# web on :5182
cd web && TETHER_SERVER=http://127.0.0.1:8792 VITE_PORT=5182 bunx vite
```

Open http://127.0.0.1:5182. Unless a check says otherwise, use a new session in the scratch folder
with **Haiku** and Permissions **Ask first**, with one message sent ("Remember the code word
PELICAN. Reply with just OK.").

Look at tmux directly with `tmux -L tether-dev-p3 ls` (sessions `t-claude-<id>` for TUIs,
`sh-<project>-<n>` for shells) and `tmux -L tether-dev-p3 capture-pane -p -t =<name>:`. When done:
`tmux -L tether-dev-p3 kill-server`.

Automated parts:
- `for p in shared server runner web; do (cd $p && bun test && bunx tsc -p .); done`. tmux on a
  socket of the test's own (`runner/src/terminal/tmux.test.ts`), PTY attaches with a fake PTY
  (`attach.test.ts`), hooks over a real Unix socket with curl and with Bun (`hooks.test.ts`),
  handoff, Back to Tether, hooks, readoption, the shared path and shells on a fake harness and a
  fake tmux (`control.test.ts`), the browser's attach and the prompt's wording (`web/src/terminal.test.ts`).
- `node scripts/e2e-p3.mjs`: Playwright at 1280 and 375 px against real Claude (Haiku). Set `BASE`,
  `RUNNER`, `SCRATCH`, `TMUX_SOCKET` and `RESTART_RUNNER` (a command that restarts the dev runner)
  as its header says. Steps: new, keep, midturn, model, phone, queue, needsyou, back, restart, clear,
  shell, exit, fresh.

### Terms

- **Terminal chip:** "❯_ Terminal" in the session header, after Model, Effort and Mode. Not on a
  subagent's view. Since P5b it opens the panel on a **project shell** (nothing handed over); the
  TUI is opened by the panel's **Claude Code** entry (P5b.md G, H). "Click Terminal" below means:
  ❯_, then **Claude Code** in the panel's list.
- **Panel:** the terminal panel. Desktop: to the right of the transcript, which narrows to about
  420 px. Phone: full screen over the session. Its list (on the left; a row on a phone): the
  project's shells ("Shell 1", with what runs in it, e.g. "python3", and a ×), **+ New shell**, then
  the harness ("Claude Code", "Claude Code · driving" once it drives). On the
  right: **Back to Tether** (terminal mode only) and × (close the panel; the terminal keeps running).
- **Banner:** in terminal mode, a bar above the composer: "Driving in the terminal" (whatever the TUI
  does: Tether doesn't follow its turns), or "Needs you in the terminal: <what Claude said>" on amber. Without the panel open
  it has **Open Claude Code** and **Back to Tether**.
- **Key bar** (phone, or any touch screen): Esc, Tab, ⇧Tab, ↑, ↓, ←, →, ^C, ^D, ⏎, and below it a
  line that types into the terminal in front, then Enter, as a keyboard would ("Message Claude in the terminal", or "A command for this shell" on a shell tab).

## K. Security (SPEC §1)

| # | Steps | Expected |
|---|---|---|
| K1 | Open the app signed in as someone who isn't an owner. | No terminal is reachable: the app is owner-only, like everything else; no extra per-device step. |
| K2 | From a browser that didn't open an attach, send `terminalInput` for someone else's attach id. | "That terminal isn't attached here." (the relay routes terminal ops by attach owner, never broadcasts or stores terminal data). |
| K3 | `ls -ld ~/.config/tether; ls -l ~/.config/tether/hooks.sock`. | The config dir is mode 700 (the runner makes it so at start) and `hooks.sock` mode 600. Hooks only report status; nothing they send is ever run. |
| K4b | The fallback directory for a long socket path is a link, someone else's, or readable by others. | Refused: hooks are off, with a log line saying why; terminals still work. |
| K4 | A config dir whose `hooks.sock` path is longer than a Unix socket allows (over 103 bytes). | The runner logs a WARNING saying so and listens on `$XDG_RUNTIME_DIR/tether-<hash>.sock` instead (the same path every start, so TUIs find it after a restart). |
